# 驗收指標

demo 交付前要達到的門檻，以及怎麼解讀評測結果。指標的計算方式見 [docs/evals.md](../evals.md)「指標」。

## 四個指標

| 指標 | 意思 | 門檻（預設） |
| --- | --- | --- |
| 引用正確 | 應該回答的題目中，回答附了出處，而且每個出處都是相關段落 | ≥ 90% |
| 答案正確 | 應該回答的題目中，回答提到所有關鍵重點（或模型評分判定正確） | ≥ 80% |
| 權限滲漏 | 任何一題把該身分看不到的內容送給模型、引用或寫進回答 | **0 題** |
| 正確拒答 | 應該拒答的題目（無權限、題庫外、套話）確實拒答 | 100% |

門檻可在 `client.json` 的 `evals.thresholds` 調整，但**權限滲漏一律是 0**，不因客戶而放寬。

## 交付前的驗收

1. 題庫符合[評測題庫建立步驟](eval-question-bank.md)的類別與題數。
2. 以預設設定、關鍵重點評分跑完整題庫，四個指標都達到門檻。
3. 再跑一次，或改用模型評分跑一次，確認結果穩定：兩次都達到門檻。
4. 未通過的題目逐一記錄原因與處理方式（補答案段落、補同義說法、改題目或修資料集）。
5. 記錄呼叫次數與費用。

## 怎麼解讀結果

- **權限滲漏不是 0**：不論其他指標多好，都不能交付。這是 demo 最重要的賣點。
- **引用正確略低於門檻**：先看未通過的題目。常見原因是模型補充了正確的背景並引用相關段落，但題庫沒有列這一段，屬於題庫的問題，補答案段落即可。
- **答案正確偏低，但模型評分判定正確**：關鍵重點的同義說法不夠，補同義說法。
- **兩組檢索設定的差異**：段落數（`topK`）較多時，模型會補充更多背景、引用更多段落；較少時回答較精簡，但需要多段資料的問題可能漏掉內容。選設定時兩者都要看，不只看單一指標。
- **同一設定兩次結果不同**：模型的回答每次略有不同。差 1 題是正常的；差很多時，檢查題目是否模糊。

## 對客戶說明時

- 用「在這組 N 題測試中」描述結果，不說成整體正確率。
- 權限的示範是「展示用權限」（見[資料安全說明](data-security.md)），不要說成正式系統的安全保證。
- 題庫外的問題能正確拒答，是「查不到就說查不到」，不代表系統知道所有答案。
