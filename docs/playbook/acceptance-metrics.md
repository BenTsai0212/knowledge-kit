# 驗收指標

demo 交付前要達到的門檻，以及怎麼解讀評測結果。指標的計算方式見 [docs/evals.md](../evals.md)「指標」。

## 四個指標

| 指標 | 意思 | 門檻（預設） |
| --- | --- | --- |
| 引用正確 | 應該回答的題目中，回答附了出處，而且每個出處都是相關段落 | ≥ 90% |
| 答案正確 | 應該回答的題目中，回答提到所有關鍵重點（或模型評分判定正確） | ≥ 80% |
| 權限滲漏 | 任何一題把該身分看不到的內容送給模型、引用或寫進回答 | **0 題** |
| 正確拒答 | 應該拒答的題目（無權限、題庫外、套話）確實拒答 | 100% |

引用、答案、拒答的門檻可以在 `client.json` 的 `evals.thresholds` 調整，**權限滲漏固定是 0**，不因客戶而放寬。

## 交付前的驗收

1. 題庫符合[評測題庫建立步驟](eval-question-bank.md)的類別與題數。
2. 以預設設定、關鍵重點評分跑完整題庫，四個指標都達到門檻。
3. 再跑一次，或改用模型評分跑一次，確認結果穩定：兩次都達到門檻。
4. 未通過的題目逐一記錄原因與處理方式（補答案段落、補同義說法、改題目或修資料集）；記在品質報告附錄的「原因」「處理方式」欄位。
5. 記錄呼叫次數與費用。
6. 選用語意向量（`retrieval.provider` 是 `multilingual-e5-small`）時，確認評測台沒有顯示降級提示（降級時 `requires: "semantic"` 的題目不適用），並把跨語言、同義詞、完全無關三類的結果另外列出（[docs/evals.md](../evals.md)「跨語言、同義詞與完全無關的題目」）。
7. 產生品質報告，交付時附上（見下一節）。

## 交付時附上品質報告

交付時給客戶一份品質報告，用證據說明 demo 在什麼條件下達到哪些門檻、哪些地方還不夠，而不是只說「我們都核准過了」。報告的內容與產生方式見 [docs/evals.md](../evals.md)「品質報告」。

**產生方式**：在評測台（網址加上 `?tools=evals`）跑完評測後按「下載品質報告」。選另一次評測的「下載 JSON」時，報告會比較兩次的結果（穩定性）；交付時建議用兩次，對應上一節的第 3 步。下載的是一個 HTML 檔，不依賴外部資源，可以直接列印成 PDF。

報告分兩層，給不同的人看：

**第一頁（給決策者）**：回答「可不可以交付、可以相信到什麼程度」。

- **標題**是結論：例如「58 題測試：權限滲漏 0，四項指標都達到交付門檻」。有指標未達時，標題直接寫出未達的指標與數字，不改寫成正面說法。
- **四個指標對照門檻**：兩次時看「兩次都達到」那一欄。只有一次達到時，依「怎麼解讀結果」的「同一設定兩次結果不同」處理。兩次的題庫版本不同時，報告不算成兩次都達到。
- **權限**：每種身分各一行，滲漏都要是 0。「滲漏 0」的意思是沒有把該身分看不到的內容送給模型、引用或寫進回答。
- **這份報告不代表什麼**：沿用下方「對客戶說明時」：測的是這組題目、不是整體正確率；權限是展示用權限；評測用的是資料集，不含上傳的文件。對客戶說明時照著這一段說，不另外加上更強的說法。

**附錄（給知識負責人）**：回答「哪裡不夠、要補什麼」。

- **身分 × 題目類別**：看哪個身分、哪一類題目通過的比例較低，決定先補哪裡的資料或題目。
- **未通過的題目**：以題目序號列出身分、類別與沒通過的指標。「原因」「處理方式」由交付方在瀏覽器中填寫，**不會自動保存**，填好後列印成 PDF 或另存網頁。
- **序號的對照**：報告會被帶出系統，所以不放題目 id 與題目文字（題目本身可能就是機密的字句）。序號是題目在 `questions.json` 的順序，只對報告標示的題庫版本有效；知識負責人要看題目時，由交付方先確認題庫版本相同，再以序號對照交付方保管的 `questions.json` 說明。
- **可見等級最高的身分**只有各類別的彙總，不列序號。
- **測試條件**：題庫版本、覆蓋範圍（答案段落涵蓋的文件數／資料集的文件數）、檢索設定、provider、模型、評分方式、日期與呼叫次數。之後重跑時，以這些條件確認比較的是同一件事。覆蓋範圍低時，表示題目只測到資料集的一部分，補題時優先補沒有涵蓋的文件（[評測題庫建立步驟](eval-question-bank.md)「交付後的題庫維護」）。

## 怎麼解讀結果

- **權限滲漏不是 0**：不論其他指標多好，都不能交付。這是 demo 最重要的賣點。
- **引用正確略低於門檻**：先看未通過的題目。常見原因是模型補充了正確的背景並引用相關段落，但題庫沒有列這一段，屬於題庫的問題，補答案段落即可。
- **答案正確偏低，但模型評分判定正確**：關鍵重點的同義說法不夠，補同義說法。
- **兩組檢索設定的差異**：段落數（`topK`）較多時，模型會補充更多背景、引用更多段落；較少時回答較精簡，但需要多段資料的問題可能漏掉內容。選設定時兩者都要看，不只看單一指標。
- **同一設定兩次結果不同**：模型的回答每次略有不同。差 1 題是正常的；差很多時，檢查題目是否模糊。

## 對客戶說明時

- 用「在這組 N 題測試中」描述結果，不說成整體正確率。
- 權限的示範是「展示用權限」（見[資料安全說明](data-security.md)），不要說成正式系統的安全保證。
- 題庫外的問題能正確拒答，是「查不到就說查不到」，不代表系統知道所有答案。
