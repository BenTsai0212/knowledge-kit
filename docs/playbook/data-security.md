# 資料安全說明

說明 demo 如何處理資料，以及哪些資料不能放進 demo。可以直接提供給客戶。

## 一句話說明

**demo 是展示用的原型，使用虛構資料。** 它示範的是「依身分看到不同內容」「附出處回答」等功能如何運作，不是可以存放真實資料的正式系統。

## demo 的資料放在哪裡

| 資料 | 存放位置 | 保存多久 |
| --- | --- | --- |
| 虛構資料集 | 打包在網頁中，開啟 demo 時下載到瀏覽器 | 關閉或重新整理頁面即消失 |
| 示範時上傳的文件 | 只在瀏覽器的記憶體中 | 重新整理頁面即消失，不上傳到任何伺服器保存 |
| 問題與相關段落 | 送到轉發伺服器，再送到 AI 模型產生回答 | 轉發伺服器不保存內容（紀錄只有時間、狀態等，不含問題與段落）；模型供應商依其商業條款處理 |
| 邀請碼 | 存在瀏覽器，用來限制使用次數 | 可隨時清除 |

## 為什麼不能放真實的機密資料

demo 為了能在任何電腦上直接打開，**整個資料集都會下載到使用者的瀏覽器**，再於瀏覽器中依身分篩選。

- 畫面上切換身分時，確實只會看到該身分能看的內容，權限規則與正式系統使用相同的資料庫機制（PostgreSQL 的列層級權限）。
- **但資料本身已經在瀏覽器裡**。懂技術的人可以從瀏覽器取得完整資料集，包括機密等級的內容。

所以 demo 的權限是「展示用權限」：用來說明正式系統會怎麼運作，不是實際的保護措施。畫面上也會標示「虛構資料」「展示用權限」。

正式系統會把資料放在伺服器，依登入身分只把看得到的內容送到瀏覽器；這屬於後續階段，不在 demo 範圍內。

## 可以與不可以

| 可以 | 不可以 |
| --- | --- |
| 依真實文件的寫法改寫成虛構內容 | 直接放入真實文件 |
| 使用虛構的人名、專案、金額 | 真實的人名、電話、email、身分證號、帳號 |
| 示範時上傳虛構或已公開的文件 | 上傳機密、個資、客戶合約、財務資料 |
| 經客戶同意後使用公司名稱與品牌色 | 未經同意使用任何公司或合作夥伴的名稱、商標 |

## 送到 AI 模型的內容

- 每次提問時，只把「問題」與「這個身分看得到、而且和問題最相關的幾個段落」送給模型；看不到的段落不會送出。
- 上傳文件後的萃取與比對，會把該文件的段落送給模型。
- 模型供應商如何保存與使用 API 的資料，以簽約或使用當時的商業條款為準；正式導入前，請由貴公司的法務或資安人員確認。

## 使用次數與費用的限制

- 每個邀請碼每天有使用次數上限，避免意外的大量使用。
- 邀請碼可以隨時停用。
- 模型的金鑰只存在轉發伺服器的設定中，不會出現在網頁或文件裡。

## 正式導入前要另外確認的事

demo 不處理以下事項，正式導入時需要另外規劃：

- 帳號登入與身分驗證
- 資料存放的地點（國家或地區）、備份與保存期限
- 存取紀錄與稽核
- 與既有系統（雲端硬碟、文件系統）的同步
- 個人資料保護與相關法規的遵循
