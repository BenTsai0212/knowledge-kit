# Data inventory

For the client to fill in. We use it to decide which documents the demo is modeled on, and each document's confidentiality level and readers.

**Important: the demo uses fictional data.** Based on the document types and writing style you describe, we write fictional documents that look similar. Real documents are not put into the demo. See [Data security](data-security.md) for why.

## How to fill it in

Each row is a *type* of document (e.g., "weekly project status report"). You do not need to list every document.

| Column | Meaning | Example |
| --- | --- | --- |
| Document type | What this kind of document is called | Weekly project status report |
| Purpose | Who looks it up, and for what | Managers check whether a project is late |
| Format | Word, PDF, Excel, slides, plain text, scanned | Word |
| Language | Chinese, English, other; mixed or not | Chinese, with technical terms in English |
| Approximate volume | Number of documents or pages | 1 per week, about 2 pages |
| Update frequency | How often it changes; whether old versions stay valid | Weekly; the new version replaces the old one |
| Confidentiality level | Using the levels from requirements checklist C1 | Internal |
| Project only | Whether only members of a project can see it | Yes, project members only |
| Readers | Which roles can see it | Project members, managers |
| Owner | Who writes it and who confirms it is correct | Project manager |
| Sample available | Can you provide a de-identified example so we can follow the writing style? | Yes, with names and amounts removed |
| Notes | Common questions, easily confused points | Many versions; people often cite an old one |

## When providing samples

- **De-identify first**: remove or replace names, phone numbers, email addresses, ID numbers, account numbers, amounts, and customer and supplier names.
- We only need excerpts that show the writing style, not complete documents.
- If you are not sure whether you may share something, do not share it. Describe in words what this type of document usually contains instead.

## How we use the inventory

1. Use "Document type" and "Purpose" to choose the set of fictional documents for the demo, 1–3 per type.
2. Use "Confidentiality level", "Project only", and "Readers" to set visibility levels, projects, and roles, and to plan the permission demonstration (the same question gives different answers for different roles).
3. Use "Update frequency" and "Notes" to plan the demonstration of conflicting old and new information.
4. Use "Language" to decide the demo's languages and whether cross-language questions are needed.
