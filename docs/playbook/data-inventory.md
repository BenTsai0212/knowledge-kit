# 資料盤點表

請客戶填寫，用來決定 demo 要以哪些文件為範本，以及每份文件的機密等級與可閱讀的對象。

**重要：demo 使用虛構資料。** 我們依照您填寫的文件種類與寫法，改寫成內容虛構、但樣貌相似的文件，不把真實文件放進 demo。原因見[資料安全說明](data-security.md)。

## 填寫方式

每一列是一「類」文件（例如「每週專案進度報告」），不需要逐份列出。

| 欄位 | 說明 | 範例 |
| --- | --- | --- |
| 文件類型 | 這一類文件叫什麼 | 每週專案進度報告 |
| 用途 | 誰會來查、查什麼 | 主管查專案是否延誤 |
| 格式 | Word、PDF、Excel、簡報、純文字、掃描檔 | Word |
| 語言 | 中文、英文、其他；是否混用 | 中文，專有名詞用英文 |
| 大約數量 | 份數或頁數 | 每週 1 份，約 2 頁 |
| 更新頻率 | 多久更新一次；舊版是否還有效 | 每週，新版取代舊版 |
| 機密等級 | 依需求確認清單 C1 的分級 | 內部 |
| 限定專案 | 是否只有某個專案的成員能看 | 是，僅專案成員 |
| 誰能閱讀 | 哪些角色能看 | 專案成員、主管 |
| 負責人 | 誰撰寫、誰確認內容正確 | 專案經理 |
| 能否提供樣本 | 可否提供去識別化的範例，讓我們參考寫法 | 可，已去除人名與金額 |
| 備註 | 常見的問題、容易混淆的地方 | 版本多，常有人引用舊版 |

## 提供樣本時

- **請先去識別化**：刪除或替換人名、電話、email、身分證號、帳號、金額、客戶與供應商名稱。
- 只需要能看出「寫法」的片段，不需要完整文件。
- 不確定能不能提供時，請先不要提供，改用文字描述這類文件通常寫些什麼。

## 我們如何使用盤點結果

1. 依「文件類型」與「用途」決定 demo 的虛構文件組合，每類 1～3 份。
2. 依「機密等級」「限定專案」「誰能閱讀」設定可見等級、專案與角色，並安排權限示範（同一個問題，不同身分看到不同答案）。
3. 依「更新頻率」與「備註」安排新舊說法不同的示範。
4. 依「語言」決定 demo 的語言，以及是否需要跨語言的題目。
