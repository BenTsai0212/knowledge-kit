# 知識圖譜、多跳路徑、時間軸（`app/src/graph/`）

以圖譜呈現**目前身分看得到**的實體與關係，找出兩個實體之間的最短路徑，並以時間軸呈現文件的先後。決策紀錄見 #31。

## 資料來源

| 資料 | 來源 | 資料表 |
| --- | --- | --- |
| 實體 | `client/data/entities.json`（之後加上萃取） | `kk.entities`（`names` 是各語言的顯示名稱）、`kk.entity_sources` |
| 關係 | `client/data/relations.json`（同上） | `kk.relations`、`kk.relation_sources` |
| 文件與段落 | `client/data/documents/*.json` | `kk.documents`（`document_date`）、`kk.passages` |
| 實體與關係類型的名稱 | `client/knowledge-model.json` 的 `label` | 不進資料庫 |

- 實體的顯示名稱用 `names[介面語言]`；`name` 是主要名稱，萃取與合併時使用（[docs/dataset.md](dataset.md)）。
- 兩位「林志明」是不同的實體，顯示名稱相同，以所屬部門的關係區分。

## 權限

三種資料一律經 `db.withIdentity()` 讀取，看得到哪些列完全交給 RLS（[docs/data-model.md](data-model.md)「權限規則」），本模組不另外判斷：

- **實體**：至少一個出處段落看得到。
- **關係**：至少一個出處段落看得到，且兩端的實體都看得到。
- **出處**：只回傳看得到的出處段落。
- **時間軸**：看得到的文件中，看得到的段落。

測試（`app/tests/graph/`）以 `app/tests/db/oracle.ts` 對每個身分（3 個角色、`null`、不存在的身分）比對，結果必須**正好**等於可見範圍（滲漏 0、漏看 0），並以「忽略身分、一律以主管查詢的資料層」做反向驗證：

| 測試 | 比對的內容 |
| --- | --- |
| `leakage.test.ts` | `readGraph()` 的實體、關係、實體出處、關係出處 |
| `search.test.ts` | 搜尋每個實體在每種語言的所有名稱：結果只含看得到的實體，看得到的都搜得到；「關聯最多」只含看得到的實體，關聯數只算看得到的關係（#199） |
| `path.test.ts` | 每對實體的路徑：有無、長度與 oracle 可見圖上的最短距離相同；每一步都是看得到的關係 |
| `timeline.test.ts` | 每種語言 × 每個實體篩選（含不篩選）的文件與段落；段落的 `entityIds` 只含看得到的實體 |

## 圖譜：`readGraph()`

```ts
const graph = await readGraph(db, "staff");
// { entities: [{ id, type, name, names, sources }], relations: [{ id, type, from, to, sources }] }
// sources: [{ id, documentId, documentTitle, language, content }]
```

一次讀出全部看得到的實體與關係（含出處段落），不依節點展開：資料集只有 14 個實體、19 個關係，一次讀出最簡單，權限也只需測試一個查詢。點出處時以 `readSource()`（`app/src/sources/source.ts`）打開原文。

## 多跳路徑：`shortestPath()`

```ts
shortestPath(graph, "person-huang-jianhong", "project-longpier");
// [{ entity: "person-huang-jianhong" }, { entity: "project-longpier", relation: "huang-works-on-longpier" }]
```

- **演算法**：在 `readGraph()` 回傳的可見圖上做 BFS，不分關係方向（方向只影響顯示）。可見圖已經過 RLS 篩選，所以路徑只會經過看得到的實體與關係，不另外查詢資料庫。
- **最大跳數**：`MAX_HOPS = 6`。超過的路徑意義不大，也避免大圖上走太遠。
- **多條最短路徑**：鄰居依（關係 id, 實體 id）排序後展開，結果固定可重現。
- **找不到**：起點或終點不在可見圖中、沒有連通、或超過 `MAX_HOPS`，都回 `null`。畫面顯示同一句固定文字，不區分原因，不透露是否因權限而找不到。
- 看不到中間節點時，即使兩端都看得到也找不到路徑。參考資料集沒有這種情況，所以 `path.test.ts` 另建小樣本（A —公開— B（機密）—公開— C）測試。

## 時間軸：`readTimeline()`

```ts
const entries = await readTimeline(db, "staff", { language: "zh-TW", entityId: "project-bluewing" });
// [{ documentId, title, date: "2026-02-10", language, passages: [{ id, content, entityIds, marks }] }, …]
```

- **單位**：文件，附上其中看得到的段落（依文件中的順序）。沒有看得到的段落的文件不列出。
- **排序**：依日期由新到舊（#42）；沒有日期的文件排在最後（`date` 為 `null`）。日期相同時依文件 id。
- **語言**：只列出與介面語言相同的文件（#31 決定 2），與問答一致。
- **依實體篩選**：只留以該實體為出處的段落，以及有這類段落的文件。`entityIds` 是以該段為出處、且看得到的實體。
- **標示**：`marks` 是已處理的說法不同與取代（「與〈文件〉的說法不同」「已由〈文件〉取代」「取代〈文件〉的說法」），只有看得到另一段時才有，見 [docs/conflicts.md](conflicts.md)「畫面」。`readSource()` 的段落也有同樣的 `marks`。
- **日期**：在 SQL 中以 `to_char(document_date, 'YYYY-MM-DD')` 轉成字串，不經過 JavaScript 的 `Date`，避免時區讓日期差一天；畫面直接顯示該字串。
- 參考資料集中，依「青翼專案」篩選時，中文與英文都能看出上市時間從第二季（較早的文件）改為第三季（2026-05-15 的進度更新）；由新到舊排列，所以第三季的進度更新在上面。上市時間的 4 段是 `project-bluewing` 的出處（#31 決定 4）。

- **節點與線**（#199）：
  - 節點是白底（`surface`，深色模式是深色底）圓形，外圈與圖示是實體類型的 `color`，圖示是 `knowledge-model.json` 的 `icon`（[client-config.md](client-config.md)「`entityTypes[]`」）；圖例是圖示＋類型名稱。
  - 節點大小＝看得到的關聯數（`nodeSize()`：32px 起，每個關聯加 4px，最多 64px）；線粗＝看得到的出處數（`edgeWidth()`：1 個 1.75px，每多一個加 0.75px，最多 5 個）。
  - 選取的節點：類型色 14% 的淡色底、陰影（cytoscape 的 `underlay`），圖示改用 `text` 色（深色模式中類型色放在淡色底上不足 3:1）。對比由 `check:client` 檢查（[client-config.md](client-config.md)「對比度」）。
  - 類型不只靠顏色區分：同一個客戶內每種類型的圖示不同（`check:client` 檢查）。
- **逐步展開**（#199）：狀態是已展開的路徑（`graph/expansion.ts`，例如 `[A, B]`），空陣列＝全部。
  - 聚焦集合＝路徑上的節點＋它們的直接鄰居（不分方向），以及這些節點之間的關係；其他節點與線變灰（`dimmed`，不隱藏，保留整體輪廓）。變灰的節點縮小到 75%，外圈與圖示改用 `border`／`textMuted`；節點仍可點，所以不降低透明度，標籤維持可讀的對比。
  - 點聚焦集合中的節點：接在路徑後面（已在路徑上時截到該處）；點變灰的節點＝「只看它」（路徑換成 `[它]`）；點空白處不清除，以「回到全部」清除。
  - 關係名稱只在選取節點（路徑的最後一個）的相連關係顯示。
  - 切換身分後，路徑截到第一個看不到的實體之前（後面的展開是從它出發的）。
  - 全部在 `readGraph()` 的可見圖上計算，不新增查詢，所以聚焦與變灰只涉及看得到的實體與關係。
- **找起點與右側面板**（#199）：
  - **搜尋**：比對主要名稱與各語言的顯示名稱（部分符合），以實體類型的 `aliasRules` 正規化大小寫、全半形與空白；名稱以查詢開頭的排前面，最多 8 筆；同名的實體附上第一個相關實體（`entityOptionLabel()`）。選了從它開始展開（`[它]`）。上下鍵移動、Enter 選取、Esc 取消。
  - **類型篩選**：圖例的每種類型有核取方塊（預設全選）；沒勾的類型的節點與它們的線變灰（不隱藏、不重排），並排除在搜尋與「關聯最多」外。`knowledge-model.json` 以外的類型不受篩選。
  - **沒有選取時**右側列出「關聯最多」的 5 個實體（看得到的關聯數，同數依名稱；沒有關聯的不列），點了從它開始展開。
  - **在問答中問**：以 `askAboutEntity`（例如「{name}的相關資訊有哪些？」）填進問答頁的輸入框並切到問答頁，不送出。
  - **多跳路徑**：找到路徑時，路徑上的節點與線以外變灰（優先於逐步展開的變灰）；清除終點後恢復。
  - **文件數**：出現的文件（實體的出處段落所在的文件，依「出處優先顯示介面語言」挑選）的數目。
  - 全部在 `readGraph()` 的可見圖上計算，不新增查詢，所以搜尋、起點清單與面板只會有目前身分看得到的實體與關係。
  - **手機寬度**：改為單欄（搜尋 → 圖 → 面板），圖的高度較低；正式的手機設計之後另外處理。
- **版面不重排**：版面只在讀入圖時排一次；展開、變灰、回到全部都只改 cytoscape 的 class，節點位置不動。切換身分或語言時圖本身改變，才重新排版。
- **畫布不移動**：cytoscape 快取容器在畫面上的位置，只在視窗大小改變、捲動與容器本身的大小改變時重新計算；容器被上方的內容推動時，滑鼠座標會換算到錯的位置。所以「已展開」那一列沒有展開時也保留高度；另外在容器或上一層的大小改變時，以及每次按下指標時，位置變了就呼叫 `cy.resize()`（`ui/GraphView.tsx` 的 `trackContainer()`，問答頁的鄰近圖也適用）。
- **動態**（`ui/motion.ts`，約 0.3–0.4 秒）：
  - 新展開的節點以 cytoscape 樣式的 transition 由小、灰轉成正常大小與類型色。
  - 新的線由關係的起點畫向終點：暫時改成虛線（線段與間隔都比線長），以 `animate()` 把 `line-dash-offset` 從線段長度動到 0，畫完後換回實線。從全部開始展開時，聚焦集合的線都算新的。
  - 畫面平滑移動，讓選取的節點靠近中央（不改縮放）；聚焦集合放不進畫面時改為把聚焦集合整個放進畫面；回到全部時顯示全貌。
  - 系統設定「減少動態效果」（`prefers-reduced-motion: reduce`）時，transition 為 0、不呼叫 `animate()`，直接套用最後的狀態；設定改變時即時更新。
- **cytoscape**：以 `import("cytoscape")` 動態載入，build 時分成獨立的 chunk（約 435 KB，gzip 約 138 KB），只用問答的人不必下載。cytoscape 自帶型別，不安裝 `@types/cytoscape`（ADR 0001「修訂」）。
- **版面**：內建的 `cose`（力導向）。節點先依順序排成一個圓作為起始位置，並設 `randomize: false`，所以同樣的資料每次的版面相同；不需要額外的版面套件。
- **出處優先顯示介面語言**（#36）：節點詳細資訊與多跳路徑的出處，都以 `ui/graph-labels.ts` 的 `sourcesForLanguage()` 決定：
  1. 有介面語言的出處時，只顯示這些。
  2. 沒有時，顯示其他語言的出處，並在每段前標示語言（以 `Intl.DisplayNames` 依介面語言產生，例如英文介面顯示「Chinese (Taiwan)」、繁中介面顯示「英文」），不讓關係看起來沒有出處。

  只影響顯示：`readGraph()` 仍回傳所有看得到的出處，權限不變；點出處打開原文的行為不變。例如英文介面中，「張雅婷負責長堤專案」有英文出處，所以只顯示英文；「黃建宏參與長堤專案」只有中文出處，所以顯示中文並標示語言。
- **切換身分或語言**：
  - 圖譜與時間軸重新讀取，之後才回來的舊結果忽略（`ui/requests.ts`）。
  - 開啟的原文由 `App.tsx` 一律關閉。
  - 選取的節點、路徑的兩端、時間軸篩選的實體，在新身分下看不到時清除，看得到時保留；路徑由新的可見圖重新計算。

## 限制


- **規模**：每次都讀出全部看得到的實體與關係，路徑在前端計算。數千個實體以內沒有問題；更大的圖需要依節點展開或在資料庫中計算路徑。
- **參考資料集的圖分成 4 個不相連的群組**（研發／青翼、業務、人資、營運／長堤），多跳路徑只出現在同一個群組內，最長 2～3 跳。
- **路徑不考慮關係的方向與類型**：例如「A 負責 B」與「B 負責 A」視為相同的連結。
- **時間軸以文件日期為準**：段落沒有自己的日期；文件沒有日期時排在最後。
- **實體沒有日期**：無法呈現「某人何時加入專案」這類實體層級的時間軸。
- **同名實體**：兩位林志明的顯示名稱相同，畫面以所屬部門區分；合併策略見 `knowledge-model.json` 的 `mergeStrategy`（萃取與合併在 Epic 第 9 項）。
