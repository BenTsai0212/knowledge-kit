# ADR 0008：視覺設計系統（Light／Dark 共用 token，證據色固定）

- 狀態：Proposed
- 日期：2026-11-11
- 決定者：@BenTsai0212
- 相關：#223、RFC 0001（中立預設主題、虛構資料標示）、[設計規格](../design.md)

## 背景

目前的介面是通用的灰藍後台：附出處、查不到就拒答、權限三個賣點，和一般按鈕長得一樣。產品的定位也從辦公室問答擴大到「上傳、建立、互動」的知識圖譜平台。

設計階段做過兩個方向：A「墨與螢光」（沉穩、閱讀優先）與 B「晶格 Lattice」（暗色、科技感）。兩者在引用標號、說法不同、字體、實體顏色、警告色上互相矛盾，不能直接當成兩個模式。

## 選項

1. **只用 A**：好讀，但不符合「知識圖譜平台」的調性。
2. **只用 B**：科技感強，但長篇中文在全暗介面上不好讀。
3. **A 當 Light、B 當 Dark，共用一份 token**：兩種模式只換顏色，行為、動態、元件形狀相同。
4. **每個客戶自訂全部顏色**：彈性最大，但「證據只用一個顏色」的規則會被各 fork 改掉。

## 決定

- **採用選項 3**。token 定義在 [docs/design.md](../design.md)「顏色 token」，對應 `client/theme.json` 的 `colors`／`darkColors`。
- **證據色固定，客戶不能改**：`mark`、`markSoft`、`markText`、`markReading` 只代表出處（引用標號、原文螢光）。主色 `primary` 只代表「可以操作」。
- **說法不同用洋紅**（新增 `conflict`），因為 Dark 的琥珀已經是證據色。
- **Dark 模式下，原文仍放在亮色紙面上**（新增 `reading`），長篇中文的可讀性優先。
- **實體顏色一律用客戶的設定**，Dark 依固定規則自動調亮，不另外維護一組。
- **兩種模式共用同一套動態**：時間與曲線相同，換主題只換顏色。

## 後果

- 好處：三個賣點在第一眼就分得出來；換客戶仍然只改 `client/`；agent 不會把引用標號「改正」成主色。
- 代價：`theme.json` 要新增 10 個鍵、改 15 個鍵的值，`theme.test.ts` 與 `app.css` 要跟著改；字型的取得方式（自備或系統字型）還沒決定。
- 後續工作（各自開 Issue）：主題 token 換新值、icon 與 favicon、動態刻度接上 `motionDuration()`、入口頁主視覺、參考情境的專案色改紫色與 `check:client` 色相檢查；手機版、無障礙與品質報告的設計另案。
