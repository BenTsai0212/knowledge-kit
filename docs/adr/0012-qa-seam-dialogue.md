# ADR 0012：問答的接縫提問與人的理解（討論版）

- 狀態：Accepted
- 日期：2026-11-15
- 決定者：@BenTsai0212
- 相關：ADR 0011（只審接縫）、#247、[docs/qa.md](../qa.md)「說法不同」「回答提到」、[docs/conflicts.md](../conflicts.md)、#377（拒答先確認）

## 背景

問答現在是「查詢版」：遇到說法不同時並列兩種說法、不選邊（`docs/qa.md` system 第 5 條），遇到同名（兩位林志明）時由模型自行處理。設計原則是「AI 把材料拼起來，解讀交給人」：AI 只在接縫處開口，給選項、接一句話，再把主導權交回給人；人的理解留下來，附在原文旁，但不改變事實。

依據：AI 不確定時才主動介入並衡量打擾的代價（[horvitz1999](../references.md#horvitz1999)）；第一人稱的保留語氣讓信任更恰當（[kim2024](../references.md#kim2024)）；只給一個假設會把人帶走（[jakesch2023](../references.md#jakesch2023)）；越信任 AI 越少批判思考（[lee2025](../references.md#lee2025)）。原型「產品原型」（查詢版對照討論版）的自測（1 人，設計者）：討論版最好，按鈕選項讓決策負擔輕、有共同參與感；擔心問多了會被打擾。

## 選項

- **在哪些接縫開口**：說法不同、同名、答案變了、答不出來（#377 已處理）。
- **提問與假設怎麼產生**：
  - A. 固定範本（依文件標題、日期差填入）：不花費用與額度，但看不懂內容，只能講時間差與不同情況。
  - B. 回答後另外呼叫模型：最自然；每次提問多一次呼叫（約 $0.01～0.04，佔每日額度，回答後再等 3～8 秒），每次措辭不同，帶立場時難以檢查。
  - C. 上傳比對說法不同時，在同一次呼叫一併產生並存下來：內容依原文產生、問答時不花費用與額度、措辭可以事先驗證；要擴充現有的比對 prompt 與資料表。
- **選了之後 AI 說什麼**：只補一句證據；或與證據不合時溫和地提出另一種可能（原型「實測 7」）。
- **人的理解**：只留給本人；或看得到兩段原文的人都看得到（附角色與時間）。
- **開關**：`client.json` 設定，或寫死。

## 決定

1. **這次的接縫只有兩種**：
   - **同名（回答前）**：問題提到的名稱對應到目前身分看得到的 2 個以上同類型實體時，先反問再回答，不呼叫模型：「公司有兩位林志明，你問的是哪一位？」，選項是 `entityOptionLabel()` 的區分（與搜尋結果、圖上節點、「接著問」相同，例如［林志明（青翼專案）］），加上［兩位都想知道］。選了之後把選擇接在問題後面送出（例如「林志明（青翼專案）的專案有哪些？」）；問題泡泡顯示原問題，下方灰字顯示補上的說明。
   - **說法不同（回答後）**：回答引用的兩段屬於一組已處理為「並存」的說法不同（`citedConflicts()`）時，回答結束後在卡片內提問一次。
   - 答案變了（首頁的「再問一次」）留到之後；答不出來由 #377 處理。
2. **一般問題不對話**：沒有接縫的回答完全照現在，AI 不多說一句。
3. **提問與假設用選項 C：上傳比對時一併產生並存下來。** 比對說法不同的呼叫（[docs/conflicts.md](../conflicts.md)）每一組多輸出兩個欄位：
   - `hypotheses`：2–3 個中立的假設，每個是第一人稱、約 12 字以內的完整句子（例如「我覺得是後來改過」「我覺得是不同的情況」）。prompt 要求不偏向任何一個、不判斷哪一份正確。
   - `evidence`：原文中最能區分這些假設的一句話（逐字引用，附它支持哪一個假設），例如進度更新中的「延後至 Q3」。
   - 驗證：假設 2–3 個、每個不超過 30 字、互不相同；`evidence` 必須逐字出現在兩段之一，否則這兩個欄位留空，該組退回固定範本（選項 A）：「我不確定這兩段的關係：可能是〈較新文件〉改過〈較舊文件〉的說法（相差 N 個月），也可能兩份講的是不同的情況。你怎麼看？」與三個固定選項［我覺得是後來改過］［我覺得是不同的情況］［我覺得有一份寫錯了］；沒有日期或日期相同時不寫月數。
   - 存在說法不同的待審資料中（與該組同一個可見範圍：兩段都看得到才讀得到），主管在待審頁也看得到假設。已經比對過、沒有這兩個欄位的舊組合用固定範本。
   - 提問固定是「我不確定這兩段的關係，你怎麼看？」，選項是存下來的假設，另有「都不是，我來說明」與「略過」。範本與固定文字在 `client/i18n/`。
4. **選了之後：補一句證據；與證據不合時，溫和地提出另一種可能一次。**
   - 選的假設就是 `evidence` 支持的：補一句證據，例如「進度更新裡寫的是『延後至 Q3』。」，然後說明會記錄下來。
   - 選的假設和 `evidence` 不合：以「另一種讀法」的外觀提出一次，例如「我想到另一種可能：進度更新裡寫的是『延後』，比較像同一個時程改過。你覺得呢？」，選項［改成「我覺得是後來改過」］［我維持原本的想法］，並附「對照原文」打開兩段。使用者維持原本的想法就照記錄，不再說服。
   - 沒有 `evidence`（固定範本）時：只用日期判斷，兩份相差一個月以上而使用者選「有一份寫錯了」才提出「可能是後來改過」；其餘只說明會記錄。
   - `evidence` 是 AI 的傾向，所以只在使用者選完之後、而且不合時才出現，每組對同一個身分只出現一次，不在提問時就顯示（避免錨定，[jakesch2023](../references.md#jakesch2023)）。
5. **人的理解（只能新增）**：新增 `interpretations`（`id`、`passage_a`、`passage_b`、`choice`、`changed_after_challenge`、`note`、`created_by`、`created_at`）。`changed_after_challenge` 記錄是否在 AI 提出另一種可能後改了選擇，供之後評估挑戰是否把人帶走。
   - 不改變事實：問答、時間軸、原文照舊並列兩種說法；理解只顯示在原文欄與說法不同的區塊旁，標「記錄」。
   - 同一個身分對同一組只問一次：已留下理解或按過略過的組不再提問（略過記在本次工作階段，不寫入資料庫）。
6. **誰看得到人的理解：看得到兩段原文的人都看得到，但要先作答才看得到同事的理解；只顯示角色與時間。** RLS：SELECT 要求兩段都看得到（與 `conflict_decisions` 相同）；INSERT 要求 `created_by` 是自己、兩段都看得到。「先作答」由畫面控制（自己還沒留下理解或略過前，不顯示別人的）。
7. **開關：`client.json` 的 `qa.dialogue`**（`true` 為討論版、`false` 為現行的查詢版）。參考情境與線上 demo 用 `true`；`false` 時畫面與現在完全相同。
8. **說話的規則與外觀**寫進 `docs/design.md`「AI 開口規則」與「AI 發言的外觀」（規格見 #380 的附錄，隨實作的 PR 寫入）。

## 後果

- **好處**：同名時不再讓模型猜；說法不同時，人的解讀被記錄下來，成為組織知道「哪裡還沒有共識」的材料（品質報告之後可以彙總）。問答時不多一次模型呼叫，也不佔每日額度。
- **代價**：多一張資料表與 RLS 測試；問答卡片多一種狀態；比對說法不同的 prompt、驗證與資料表都要擴充（每份有說法不同的文件多幾百個輸出 token）；AI 的「另一種讀法」可能是錯的，人仍可能被帶走（[chiang2024](../references.md#chiang2024)），以 `changed_after_challenge` 留下紀錄。
- **限制**：規則與外觀來自設計者自測與文獻，沒有多人實測；理解只存在瀏覽器的記憶體資料庫，重新整理即消失；角色層級的身分，同角色的人看不出是誰。
- **後續工作**（依序各一個 PR）：
  1. 本 ADR。
  2. 比對說法不同的 prompt 與驗證加上 `hypotheses`、`evidence`，存進說法不同的資料（migration：說法不同的資料表加欄位）、`docs/conflicts.md`、單元測試。
  3. migration（`interpretations`）、RLS 與滲漏矩陣、`store.ts`、單元測試。
  4. 同名的反問：判斷、選項、送出時補上說明、E2E。
  5. 說法不同的提問、選後補充與溫和挑戰、人的理解的顯示（原文欄、說法不同區塊）、`client.json` 開關、`docs/design.md`（AI 開口規則與外觀）、E2E。
- **之後另開 Issue**：答案變了（「再問一次」時比對）；品質報告彙總人的理解與挑戰後改變選擇的比例；以 Claude Design 的畫板做視覺對齊。

## 設計依據

- 只在接縫開口、衡量打擾：[horvitz1999](../references.md#horvitz1999) → 文獻
- 第一人稱、保留語氣、多個假設：[kim2024](../references.md#kim2024)、[jakesch2023](../references.md#jakesch2023) → 文獻
- 討論版優於查詢版、按鈕選項負擔輕：原型「產品原型」→ 自測（1 人，設計者）
- 溫和挑戰有來回感、不能長得像錯誤：原型「實測 7」→ 自測（1 人，設計者）；挑戰可能帶偏人：[chiang2024](../references.md#chiang2024)、[sarkar2024](../references.md#sarkar2024) → 文獻
- 不透露看不到的內容：#247 → 專案規則
