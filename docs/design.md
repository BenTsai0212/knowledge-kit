# 視覺與動態設計規格 v1

決策與理由見 [ADR 0008](adr/0008-design-system.md)；本文件是實作依據。設計稿在 Claude 的設計畫布上（#223），本文件寫出規則與數值；版面與元件樣式見畫板（下一段）。

**優先順序**（#329）：權限與行為的決定（#247 等 Issue 的 `## 決定`、ADR）＞ 畫板 ＞ 本文件的文字。視覺（版面、尺寸、層次、元件樣式）以畫面流程圖引用的畫板為準，原始碼在 [design/v1/boards/](design/v1/boards/README.md)；本文件是規則與數值的文字說明，與畫板不一致時以畫板為準，與決定衝突時以決定為準（見 [設計稿 v1 總覽](design/v1/README.md)）。

**設計從 [設計稿 v1 總覽](design/v1/README.md) 開始**：有哪些畫面、畫面之間怎麼切換、使用者流程與已定的決策都在那裡；本文件是各畫面的數值與規則。

## 三條原則

1. **出處是主角**：證據色只用在引用標號與原文螢光，介面其他地方不用。
2. **誠實的空白**：查不到、說法不同、空狀態都是設計過的狀態：虛線框、說明原因、給下一步；不用紅色、不搖晃。沒有權限的內容當作不存在，不設計成「被隱藏」的狀態（見下方「沒權限」）。
3. **動態只解釋因果**：畫面動，是為了說明東西從哪裡來、往哪裡去；減少動態時一律直接到位。

### 引用標號的三個狀態

| 狀態 | Light（底／字） | Dark（底／字） |
| --- | --- | --- |
| 預設 | `markSoft`／`markText`，內框 1px `mark` 84%＋`markText` | `markSoft`／`markText`，內框 1px `mark` 40%＋`markSoft` |
| hover | `mark`／`markText`，內框 1px `mark` 73%＋`markText` | `mark` 17%＋`markSoft`／`markReading` 90%＋`text`，內框 1px `mark` |
| 選取（原文已開） | `text`／`mark` | `mark`／`markSoft` |

- 「A 百分比＋B」是 `color-mix(in srgb, var(--color-A) 百分比, var(--color-B))`；不另設 token，證據色只由 `mark`、`markSoft`、`markText`、`markReading` 決定（#225 決定 1）。比例同時寫在 `scripts/check-client.mjs` 的 `CITATION_MIX`，`check:client` 依此檢查對比（[docs/client-config.md](client-config.md)「對比度」）。
- 與設計稿的差異：Light 的兩個內框比設計稿（`#E8B800`、`#C9A400`）稍暗；Dark 預設內框用 40%，對 `surface` 3.3:1（設計稿的 `#7A5A20` 只有 2.9:1）；Dark 選取的字用 `markSoft`（設計稿 `#1A1200`），對 `mark` 7.8:1。

原文螢光：Light 用 `mark`；Dark 的原文放在 `reading` 紙面上，用 `markReading`。

### 實體顏色

- 客戶在 `client/knowledge-model.json` 只設定一個顏色；Light 原樣使用，對 `surface` 至少 3:1（圖形元件標準）。
- Dark 保留色相與彩度，把 OKLCH 亮度提高到至少 0.75：`oklch(from var(--entity) max(l, 0.75) c h)`。
- 實體一律「形狀＋顏色」雙重區分：人員圓形、部門圓角方形、專案小圓角方形。
- 圖譜（#240，[docs/graph.md](graph.md)「節點與線」）：節點是類型色填色、`surface` 色圖示，形狀與入口頁主視覺相同；Dark 與主視覺一樣以 `color-mix(in srgb, 類型色 75%, text)` 近似上面的公式。選取是 4px `surface` 間隙＋3px `text` 外環、名稱反白（#336；展示模式是 `background` 間隙＋2px 外環）；變灰 45% 不透明（「只看它」15%）。
- 圖譜的實體面板（#240）：類型徽章是類型色 14% 淡底＋`text` 字，前面是類型的形狀（Dark 的形狀以同一個公式調亮）；「出現的文件」的原文片段放在 `reading` 紙面，實體名稱用 `markReading`（[docs/graph.md](graph.md)「找起點與右側面板」）。
- 參考情境「專案」原本的 `#B26A00` 在 Dark 推導後接近證據琥珀，已改為紫色 `#7A52C7`；`check:client` 在實體色相與證據色相差小於 25° 時警告（#229，[docs/client-config.md](client-config.md)「對比度」）。設計稿上的 Dark 實體色是目測近似值，實作以公式算出的值為準。

## 表單元件

不用瀏覽器的系統控制項配色（#239；`app/src/ui/app.css`，結構測試在 `theme.test.ts`）。

- **輸入框、下拉選單、多行文字**：底 `surface`、字 `text`、框線 `border`、placeholder `textMuted`；停用時不透明度 0.5，不換底色。
- **下拉選單**：自繪箭頭（`textMuted`），Light／Dark 相同。
- **核取方塊、單選鈕**：保留原生外觀，`accent-color` 為 `primary`。
- **檔案選擇**（`FilePicker.tsx`）：原生 `input[type=file]` 視覺上隱藏，仍可聚焦、以鍵盤開啟；旁邊是次要按鈕外觀的自訂按鈕與已選檔名（尚未選檔時顯示 `fileNone`），文字在 `client/i18n/`。鍵盤聚焦時焦點框畫在自訂按鈕上。
- 焦點框沿用上表的 `:focus-visible`。

## 狀態的共同語言

- **拒答**：虛線框原地出現，說明「找不到可以回答這個問題的資料」，列出「可以試試」。
- **沒權限**：沒有權限的內容當作不存在，不透露是否有看不到的內容（[qa.md「拒答」的「不透露是否有看不到的文件」](qa.md#拒答)）。看不到的資料在 RLS 就濾掉，畫面不顯示數量、月份、權限等級、上鎖框或任何「有東西被隱藏」的痕跡；拒答不區分「資料沒寫」與「沒有權限」。要展示權限差異時，說明目前身分**看得到什麼**，不說明看不到什麼。身分徽章固定是 `text` 底、`background` 字。
- **說法不同**：兩種說法並列，`conflict` 色，三個決定按鈕；被取代的說法劃線但保留出處。
- **空狀態**：虛線框＋一個線條圖示＋原因＋最多兩個下一步，不用插圖。
  - 實作（#245）：共用 `app/src/ui/EmptyState.tsx`（圖示與「最多兩個」在 `empty-state.ts`）。虛線框與圖示用 `textMuted`，標題粗體、`text` 色；第一個下一步是主要按鈕，第二個是次要按鈕；文字不用驚嘆號。
  - 套用的地方：問答尚未提問（從預設問題開始：焦點移到第一個預設問題）、圖譜沒有實體與上傳不能上傳（切換身分：焦點移到頁首的身分選單）、找不到路徑（換一個終點：清除終點並聚焦）、時間軸沒有文件或篩選後沒有符合的文件（回到全部；篩選後全部不符合時以空狀態取代全部變淡的清單）、待審清空（到圖譜查看、再上傳一份；不能上傳的身分只有前者）、回報清單為空、評測尚未執行（執行評測，與設定區的「開始評測」相同，文字不同以免兩個同名按鈕）。
  - 原因文字只說明目前身分的資料，不寫「沒有權限」、不顯示數量；「切換身分」旁不說明切換後會多看到什麼（#245 決定）。標題沿用原本的介面文字。
- **demo 標示**：每個畫面都看得到「虛構資料」「展示用權限」（RFC 0001）；線上 demo 的問答與上傳頁顯示 `demoQaNotice`、`demoUploadNotice`。

## 動態

畫布上的 `@keyframes` 與使用方式逐字放在 [`design/motion-reference.css`](design/motion-reference.css)，每個元素的延遲、時間對應的刻度與無法照抄的例外在 [`design/motion-reference.md`](design/motion-reference.md)（#249）。實作照抄參考檔，`app/src/ui/motion-reference.test.ts` 檢查 `app.css` 的 keyframes 與參考檔一致。

### 原則

1. **因果**：東西從觸發它的地方出現，消失時往它去的地方走。
2. **真實進度**：等待時顯示真的數字（段落數、批次、MB、第幾題），不用假的轉圈與進度條。
3. **隨時可中斷**：動畫中仍可操作，新的操作直接接手。
4. **不懲罰**：錯誤、拒答不搖晃、不閃紅。
5. **減少動態**：`prefers-reduced-motion` 時全部 0ms；等待改用文字與數字。
6. **證據最後到**：所有「長出東西」的時刻都依「文件 → 結構 → 證據」的順序（與 icon 相同）。

Light 與 Dark 共用同一套時間與曲線。

### 刻度

| 名稱 | 時間 | 曲線 | 用在 |
| --- | --- | --- | --- |
| fast | 120ms | `cubic-bezier(.2,0,0,1)` | 按下、hover、勾選、標號變實心、所有退場 |
| base | 220ms | 同上 | 面板、列、句子、toast、對話框、語言與主題交叉淡換 |
| expand | 300ms | 同上 | 列的展開與收合、圖譜節點展開（沿用 `EXPAND_MS`） |
| sweep | 400ms | 同上 | 原文螢光刷亮、萃取底線、圖譜平移（沿用 `PAN_MS`） |
| settle | 520ms | `cubic-bezier(.3,1.5,.5,1)` | 只給「新的知識」：引用標號、核准後的節點、icon、數字跳動 |
| progress | 實際時間 | `linear` | 下載、萃取批次、評測題數、路徑脈衝（每跳 300ms）、toast 倒數 |
| stagger | 60／80ms | — | 清單 60ms、回答的句子 80ms；超過 6 項後不再延遲 |

退場一律用 `cubic-bezier(.4,0,1,1)`。所有時間經過 `app/src/ui/motion.ts` 的 `motionDuration()`。progress 的 `linear` 是 `--ease-linear`（#244）。

- 結構與減少動態效果的檢查：`ui/global-motion.test.ts`、`ui/dialog-motion.test.ts`、`ui/gone-motion.test.ts`、`ui/cross-fade.test.ts`，E2E 是 `e2e/motion.spec.ts`。減少動態效果時不做轉場、消失的文件直接移除。

### 入口頁主視覺

入口頁左側是沒有文字的知識圖譜動態，右側是邀請碼面板。

- **三層景深**：遠景 26 個模糊小點（`translateZ(-520px)`、blur 1.2px）、中景 16 個半透明節點（`-220px`）、前景是參考情境的 14 個實體與關係；整個場景在 `perspective: 1100px` 中約 26 秒擺動一次（rotateY ±9°、rotateX ±5°），產生視差。
- **連結的動態**：進場時遠景、中景、前景依序出現；之後關係線上有光點流動（其中一條是證據色），每隔約 2.5 秒在兩個原本沒連線的節點間畫出新連線、停留後淡去；前景節點各自輕微浮動，3 個核心節點週期性發出光暈。
- 預設 Dark；減少動態時顯示靜止的完整網路。

實作（#228）：

- 入口頁是 `App.tsx` 的 `main.entry`：左側主視覺 `app/src/ui/EntryHero.tsx`，右側是邀請碼表單與語意模型的下載進度（`RetrievalNotice`）；寬度 1024px 以下（手機與平板）主視覺在上（高 330px）、面板在下。「虛構資料」「展示用權限」沿用左側導覽頁首的標示。
- 版面是 `app/src/ui/entry-hero.ts` 的純函式（固定亂數種子）：前景取 `client/data/` 中關係最多的 18 個實體（參考情境是全部 14 個），以力導向排版，形狀依類型的圖示（人員圓形、部門圓角方形、專案小圓角方形），填色是類型色；遠景與中景各連最近的兩個鄰居；新連線 4 條、每 2.5 秒一條。關係最多的 3 個節點是發光的核心節點；流動光點最多 6 條線，第一條用 `mark`。
- 動態全部是 `app.css` 的 CSS 動畫（`kOrbit`、`kPop`、`kFloat`、`kTwinkle`、`kDraw`、`kTravel`、`kForm`、`kGlow`），不用 JS 計時器；keyframes 與時間照抄 [`design/motion-reference.css`](design/motion-reference.css)「補齊 · 入口」（線段的 `pathLength` 是 1，`kFloat`、`kGlow` 是例外，#249）。主視覺在表單畫出後的下一個畫格才繪製。持續循環的裝飾動畫不套用「刻度」（`motion.test.ts` 排除 `.hero`，數值由 `entry-hero.test.ts` 檢查）。
- 低階裝置（`navigator.hardwareConcurrency` 或 `deviceMemory` 為 4 以下）：遠景 10、中景 8 個節點，遠景不模糊。
- 手機（≤ 600px，`layout.ts` 的 `useLayout()`，#255）：前景取關係最多的 9 個（`HERO_PHONE_FRONT`，減半），遠景不模糊（`hero--phone`）。1024px 以下（手機與平板）輸入框與按鈕高 52px、文字連結的觸控範圍 44px；E2E 見 `e2e/entry-touch.spec.ts`。
- 主視覺是裝飾（`aria-hidden`），不含文字。
- 與規格的差異：主題跟隨系統設定（Light／Dark 都成立），不強制 Dark；Dark 的實體色以 `color-mix(in srgb, 類型色 75%, text)` 調亮，近似「實體顏色」的 OKLCH 公式（結構測試不接受 `oklch()`）。

## 大量節點時的圖譜

參考情境只有 14 個實體；客戶的資料可能有數百個。圖譜依「目前身分看得到的節點數」切換呈現方式，**先看結構，再看細節**（#252）。

### 三層語意縮放

| 層級 | 顯示 | 進入方式 |
| --- | --- | --- |
| 1 · 全覽 | 群組泡泡與聚合線 | 預設（節點數超過門檻時） |
| 2 · 群組 | 選取的群組展開成群內節點；其他群組縮成 60px 泡泡、75% 不透明，停在畫面邊緣 | 點泡泡 |
| 3 · 細節 | 以一個實體為中心：直接關係與名稱；二度關聯 45% 不透明、虛線；群內其他成員收成「＋N 位成員 · 展開」晶片 | 點節點、搜尋名稱 |

| 可見節點數 | 桌機 | 手機（≤ 600px） |
| --- | --- | --- |
| 全部節點＋全部標籤 | ≤ 60 | ≤ 30 |
| 從全覽開始，展開一群才畫群內節點 | 61–300 | 31–150 |
| 只顯示群組，展開時才載入群內節點；大群再分子群 | > 300 | > 150 |

### 群組與聚合

- **分群**：先依知識模型中的「容器」類型（部門、專案）；沒有容器類型時用社群偵測自動分群，群組名稱取群內關聯最多的實體。
- **泡泡**：直徑 `44 + 12 × √實體數` px；邊框 2px 類型色、底色是類型色 12% 的淡色；中間是實體數（`fonts.display`）、群組名稱，以及群內類型組成的三個小點。
- **聚合線**：兩群之間有 2 段以上關係時合併成一條，線寬 `1 + 0.45 × 段數` px，中點標上「N 段」（`fonts.mono`、`surface` 底）。
- **只計算看得到的**：泡泡的實體數、聚合線的段數只計算目前身分看得到的實體與關係（RLS 濾掉之後）；切換身分時數字跟著變，不顯示也不暗示看不到的部分（見「狀態的共同語言」的「沒權限」）。

### 標籤、導覽與清單模式

- **標籤要掙來**：第 2 層只顯示群內關聯最多的前 10% 節點與選取節點的名稱，其他節點在滑過、聚焦或選取時才顯示；第 3 層全部顯示。
- **麵包屑**：圖譜上方顯示「全部 › 群組 › 實體」，點任一層回去；搜尋名稱直接跳到第 3 層。
- **篩選**：類型篩選與「只顯示關聯 ≥ N」，篩選後重新計算門檻。
- **清單模式**：「圖譜｜清單」切換，清單以文字列出同一份資料（群組 → 實體 → 關係），給鍵盤與螢幕報讀器使用者。

### 動態與效能

- 切換層級是語意縮放：泡泡放大成群內節點（expand），畫面平移到該群（sweep）；返回時節點收回泡泡。減少動態時直接切換。
- 可見節點超過 150 個時，關閉節點浮動與彈簧；排版結果依群組快取；畫面外的節點不畫標籤。

## 手機與平板

### 斷點

| 寬度 | 版面 |
| --- | --- |
| ≤ 600px（手機） | 頂端列＋底部分頁列；原文、身分與語言、實體改用底部面板 |
| 601–1024px（平板） | 左側 72px 圖示導覽列＋兩欄；原文與實體從右側滑出覆蓋（最寬 420px），背後加 `overlay` |

### 手機的共同結構

- **頂端列**（60px）：產品 icon、客戶名稱、右側身分徽章（`text` 底、`background` 字，按下打開身分面板）；下方一行「虛構資料」「展示用權限」標示。

- **底部面板**：圓角 24px、上方 40×5px 拖曳把手；往下滑、按關閉或 Esc 關閉；背後加 `overlay`；開啟時焦點移入面板、關閉時回到觸發的元件。

### 問答（手機）

- 預設問題一行、橫向滑動；輸入框與提問按鈕固定在分頁列上方。
- 引用標號高至少 24px，觸控範圍以內距補到 44px。
- 「回答提到」的實體一行、橫向滑動。
- **原文面板**：點引用標號時從底部升起，高 74%；標題列有「出處 N／M」與上一個、下一個出處（44px）；原文放在 `reading` 紙面、引用段落用 `markReading`；下方「在圖譜中查看」「回報有錯」。
- **身分與語言面板**：高 66%；身分以單選卡列出，每個身分附一句「看得到什麼」的說明（例如「公開文件」），**只說明看得到的範圍，不說明看不到什麼**；說明文字放 `client/`。語言是分段切換；「更換邀請碼」也在這個面板。

### 圖譜（手機）

照畫板 `G-Mobile-Graph` 第 2、3 張（#357；第 1 張的入口已由 `K-Mobile` 取代）：

- 圖譜佔滿頂端列與分頁列之間；上方一列是搜尋框（放大鏡 icon、placeholder「搜尋名稱」）＋篩選圖示按鈕（打開「篩選與找路徑」底部面板），下一列是「圖譜｜清單」分段切換（`surfaceRaised` 的槽，選取的一段是 `surface` 底、粗體）。

- 手勢：單指拖曳平移、雙指縮放、點節點打開實體面板。
- **實體面板**：點節點後，該節點平移到上半部中央，面板停在 56% 高；往上拉到全高。內容依序是類型膠囊、名稱與「關聯 N · 文件 N」（同一列）、「在問答中問」（主要按鈕）與「只看它」（等寬、48px）、相關實體每則一列（類型的形狀、名稱、右側關係名稱）、出現的原文片段（`reading` 紙面）。

### 入口（手機）

主視覺在上、高 330px（與「日常工具」的「登入」相同）：前景節點數減半、遠景不模糊；邀請碼表單在下，維持完整大小（輸入框與按鈕高 52px）；語意模型的下載進度放在表單下方。

### 時間軸、上傳、待審、評測台與更多（手機）

沿用手機的共同結構。分頁列依身分只列可用的頁面：一般員工 4 個；主管有「更多」，收納待審與評測台（加入首頁後的分配見「日常工具」）。

- **時間軸**：日期欄縮到 46px，卡片佔滿其餘寬度；依實體篩選的晶片一行、橫向滑動；不符合篩選的卡片變淡（45%），不移除。
- **上傳**：五個步驟縮成一條進度列（每步一段，進行中的一段依真實進度填滿），下方一行寫目前步驟與真實批數（例如「模型萃取 第 2／3 批」）。萃取在背景執行，可以切到其他頁；完成後「上傳」分頁的小點亮起。原文預覽放在 `reading` 紙面，類型色底線照桌機。
- **待審**：上方是可橫向捲動的分段切換（待審、已退回、已處理的說法不同、回報）；文件卡片的每一項一列。不需要決定的項目直接「退回／核准」；需要決定的（缺語言的名稱、合併對象、說法不同）只顯示一行摘要與「›」，點了打開底部面板處理。「核准這份文件的全部」固定在畫面下方。
- **評測台**：手機上以「看結果」為主：設定收合成一列（「A topK 5 · B topK 8 ›」）；四項指標兩欄排列，附「✓ 通過（≥ 門檻）」；題目一題一列，預設只顯示兩組不同的題目，點一題打開底部面板看回答與引用；「下載品質報告」在最下方。
- **更多**（主管）：清單列出待審（數量直接標在這裡）與評測台；評測台只在網址帶 `?tools=evals` 時出現。

### 平板

601–1024px。代表尺寸：直向 820×1180、橫向 1024×768。

- **導覽列**：左側 72px，產品 icon、各頁籤（圖示＋11px 標籤，項目 60×56px）、底部是身分的頭像。選中用 `primarySoft` 底、`primary` 字。依身分只列可用的頁籤；主管 7 個也放得下，平板不需要「更多」。
- **主內容**：直向單欄，卡片可兩欄並排（例如首頁的「問過的問題」與「最近新增的文件」）；橫向也維持一欄。原文與實體一律用滑出面板，不常駐第三欄。
- **滑出面板**：從右側滑入（`expand`），最寬 420px（實體面板 400px），背後加 `overlay`，不推擠主內容；點背景、✕、`Esc` 或向右滑關閉；開啟時焦點移入面板，關閉後回到觸發的元件。面板內容與桌機右欄相同。
- **圖譜**：選取的節點平移到面板左側的可見區。
- **鍵盤**（平板接鍵盤時）：Tab 順序是導覽列 → 主內容 → 面板；面板開啟時焦點留在面板內。
- 登入頁沿用手機版（主視覺在上、表單在下）；展示模式沿用 1920×1080 的規格縮放，不另外設計。

## 展示模式

`?mode=presentation`（`docs/qa.md`「展示模式」）是對客戶簡報用的畫面：**主持人在會議室投影，客戶坐在 5 公尺外**（#258）。

### 原則

1. **遠處也看得清楚**：以 1920×1080 投影為準，不用小於 16px 的字。
2. **照劇本走**：`client/scenarios.json` 的情境與問題是劇本，主持人一題一題往下點。
3. **身分是主角**：身分是頂端最大的切換；「身分對照」把同一題用所有身分並排回答。
4. **主持人不找滑鼠**：方向鍵換題、數字鍵換身分。

### 字級與主題

展示模式時根元素加 `data-mode="presentation"`，以 `--present-*` 變數覆蓋字級；顏色 token 不變。

| 元素 | 一般 | 展示模式 |
| --- | --- | --- |
| 內文、清單 | 15px | 20px |
| 問題泡泡 | 15px | 36px、700 |
| 回答 | 16px | 28px、行高 1.7 |
| 引用標號（高） | 22px | 36px |
| 原文面板 | 15px | 22px |
| 頁籤、身分、按鈕（高） | 44px | 56px |
| 圖譜節點標籤 | 12px | 18px（選取的實體 26px） |
| 「虛構資料」「展示用權限」 | 11–12px | 16px |

**預設 Light**（不跟隨系統）：投影機在有燈光的會議室裡，深色畫面容易灰掉。主持人可用快捷鍵 `T` 切換。

### 版面

畫面照畫板 `H-QA`、`H-Graph`（[boards](design/v1/boards/README.md)，#349）。

- **頂端列**（96px）：產品 icon、客戶名稱，下方一行 `textMuted` 小字「虛構資料 · 展示用權限」；「問答｜圖譜」是 `surfaceRaised` 底的分段切換（選中 `surface` 底）；右側是「身分」標籤＋身分分段切換（每個身分前標快捷鍵數字，選中 `text` 底）與外框按鈕「身分對照 C」。
- **劇本**（左欄 440px）：上方「劇本」與右側「第 N／M 題」；每個情境一組，標題旁是情境身分的膠囊（`text` 底）；問題是 56px 高的按鈕，前面是編號（mono），目前題目以外已問過的改標 ✓（目前的題目一律是編號），目前的題目用 `primary` 框線與 `primarySoft` 底。**點劇本的問題時，自動切到該情境的身分再送出**，身分徽章以 settle 跳一下。
- **回答**：問題是 `text` 底、`surface` 字的大字泡泡（36px）；回答是下方獨立的卡片（28px）；引用標號 36px 高、仍是證據色系；說法不同照常並列。自由提問是單行輸入列，在回答下方。
- **原文**：從右側滑入、浮在對話上的圓角卡片（寬 620px、陰影），上方「原文 · 出處 N」與「關閉 Esc」；原文在 `reading` 紙面、22px、引用段落用 `markReading`。`Esc` 關閉，焦點回到引用標號。
- **身分對照**：同一題以每個身分各送出一次，依身分順序並排成欄（參考情境 3 欄），目前身分的欄用 `primary` 框線。外層不套卡片，題目用問答的大字泡泡，每欄的身分是膠囊、各欄等高；對照時隱藏輸入區。
  - 每欄各自以該身分送出、各自依 RLS 回答，與一般提問完全相同。
  - 拒答與一般拒答相同（「找不到可以回答這個問題的資料。」與下一步），不提示看不到什麼（見「狀態的共同語言」的「沒權限」）。
  - 送出次數等於身分數，計入每日提問次數；線上 demo（`VITE_ONLINE_DEMO`）可關閉此功能。
- **圖譜**：節點與標籤放大；選取實體以外的節點降到 28% 不透明，選取的關係用 `primary` 加粗並標上關係名稱。畫布不套卡片、填滿左側，麵包屑「全部 › 名稱」在左上；右側是浮動的實體卡片（類型膠囊、名稱 44px、「關聯 N · 出現在 N 份文件」、等寬的按鈕 64px 高、每個實體一列的關聯（多則關係合併成「隸屬 · 負責」）、底部的原文片段）。不顯示搜尋、篩選與找路徑。
- **底部提示列**（52px）：列出目前畫面常用的快捷鍵。

### 主持人快捷鍵

只在展示模式、且焦點不在輸入框時作用。

| 按鍵 | 作用 |
| --- | --- |
| `→`／`←` | 下一題／上一題（照劇本順序，自動切身分並送出） |
| `1` `2` `3`… | 切換到第 N 個身分 |
| `Q`／`G` | 問答／圖譜 |
| `S` | 打開或關閉目前回答的原文（出處 1） |
| `C` | 身分對照 |
| `T` | 切換 Light／Dark |
| `←`／`→`（圖譜） | 在相鄰節點間移動鍵盤焦點；`Enter` 選取；`A` 在問答中問 |
| `?` | 顯示快捷鍵表 |
| `Esc` | 關閉原文、身分對照、快捷鍵表；圖譜回到全部 |

### 隱藏與保留

- **隱藏**：時間軸、上傳、待審、評測台（現行）；「回報有錯」、「這次的問題」、「更換邀請碼」。語意模型的下載進度縮成頂端一個小點，完成後消失。
- **保留**：「虛構資料」「展示用權限」標示（RFC 0001，字級不縮小）、身分與語言切換、出處。
- **仍不是權限防線**：只改畫面；資料的可見範圍仍由 RLS 依身分決定。

## 錯誤與額度

`/api/ask` 與前端的錯誤類型見 [qa.md「錯誤」](qa.md#錯誤)。這裡依「使用者可以做什麼」分成 5 類，每一類有固定的位置與下一步；文字放 `client/i18n/` 的 `errors`。

### 原則

1. **一句話說清楚誰能做什麼**：你可以再試、你要改問題、明天再來、要找管理者。不出現技術術語；錯誤代碼只放在可展開的細節裡。
2. **出現在發生的地方**：問題本身的錯在輸入框；這一題的錯在回答的位置；影響整頁的才放在頁面頂端。不彈出視窗。
3. **不懲罰、不搞丟**：不搖晃、不整片紅；`danger` 只用在輸入框邊線。失敗時問題文字留在輸入框，已收到的回答保留。
4. **不假裝知道**：前端不知道剩餘提問次數（Worker 只在用完時回 429），不顯示倒數或「剩 N 次」，只在真的用完後說明。

### 五類

| 類別 | 錯誤類型 | 位置 | 畫面與下一步 |
| --- | --- | --- | --- |
| 暫時的問題 | `upstream_overloaded`、`upstream_timeout`、`upstream_error`、`limit_unavailable`、`network`、`unexpected_response`、`upstream_interrupted` | 回答的位置 | 中性的卡片：訊息＋「重新提問」（同一個問題成為新的一題）。中斷時保留已收到的文字、變淡並標「回答不完整」。`network` 另在頁面頂端顯示離線提示，連線恢復（`online` 事件）後自動消失 |
| 問題要改 | `empty_question`、`question_too_long`、`prompt_too_long` | 輸入框（`prompt_too_long` 在回答的位置） | 輸入框邊線換 `danger`、下方說明；接近 500 字時顯示字數（例如「523／500」），超過時停用提問，不送出所以不計次。`prompt_too_long` 的卡片附「縮短問題」，按下回到輸入框並保留文字，這一題標「沒有送出」 |
| 今天用完了 | `daily_limit`、`global_daily_limit` | 輸入框上方 | 常駐的說明條（時鐘圖示）＋停用輸入框與預設問題；`global_daily_limit` 說明「所有使用者共用」與恢復時間 |
| 需要管理者 | `unknown_model`、`misconfigured`、`upstream_quota`、`forbidden_origin`、`invalid_request`、`method_not_allowed` | 對話區頂端 | 「這個 demo 暫時無法回答問題」＋原因一句＋可展開的「給管理者的細節」（錯誤代碼與時間，`fonts.mono`）。`invalid_request`、`method_not_allowed` 的下一步是「重新整理頁面」。輸入框保持可用 |
| 模型無法回答 | `upstream_refusal` | 回答的位置 | 比照拒答：虛線框、「可以試試」的下一步；不是錯誤樣式 |

### 額度用完之後

- 只停用「提問」：輸入框與預設問題變成停用狀態，文字改為原因；圖譜、時間軸、原文與已問過的回答照常可用（說明「圖譜、時間軸與原文仍可以瀏覽。」）。
- 停用狀態只記在這個分頁的記憶體；重新整理後可以再試，由 Worker 決定。
- 展示模式用同樣的元件、依展示模式字級放大。身分對照中途用完時，已完成的欄保留，之後的欄顯示額度訊息、不再送出。
- 上傳、萃取、比對、待審、回報的錯誤已各自有畫面（`uploadErrors`、`extractErrors`、`reviewErrors`），沿用原則 2、3。語意模型下載失敗沿用現有的降級提示。

## 品質報告的列印版面

內容與機密規則見 [evals.md「品質報告」](evals.md#品質報告)，本節只定版面。給決策者看第一頁、給知識負責人看附錄。

- **A4 直式兩頁**：第一頁 30 秒讀完；附錄從新的一頁開始。
- **第一頁**：頁首（產品名、客戶、評測日期、題庫版本）；結論式標題；四項指標的條狀圖（墨色）對照門檻（虛線），旁邊是第二次的結果與「✓ 兩次」；權限只講每個身分的「滲漏 0 題」與一句意思；最後是「這份報告不代表什麼」。
- **附錄**：身分 × 題目類別的通過數（✕ 標出有未通過的格）；未通過的題目表（序號、身分、類別、沒通過的指標、可填寫的原因與處理方式）；測試條件。
- **黑白可讀**：通過與否用 ✓／✕ 與文字，不靠顏色；底色只用淺灰。未達時條狀圖不改顏色，只加粗門檻線、該列標「✕ 未達」。
- **可填寫的欄位**：螢幕上是虛線框；列印時變成底線，並隱藏上方的說明條。
- **字型**：系統字型堆疊，不用外部字型；icon 用內嵌的單色版。
- 頁尾左邊「客戶 · 品質報告」、右邊「第 N／M 頁」。未通過的題目多時附錄延續到第 3 頁；英文版面也可能超過兩頁，見「英文版面」。
- **版面的依據**（#347）：畫板 `J-Report`（`docs/design/v1/boards/J-Report.dc.html`）；各身分是一張卡片（「身分 · N 題」與大字的「✓ 滲漏 0 題」），測試條件是兩欄的名稱與值。

## 日常工具

knowledge-kit 是展示與 fork 的起點，本身沒有日常使用的需求；日常工具的畫面是**展示**「這套系統可以每天用」，fork 到客戶時才成為產品。在 knowledge-kit 中資料仍只在瀏覽器記憶體，重新整理就重來；fork 時再接持久化的儲存（RFC 0001 第 3 階段）。通知只在產品內（首頁與導覽列的數字），不寄信。

### 原則

1. **每次回來都有起點**：登入後先到首頁，不從空白的輸入框開始。
2. **跨身分的事要接回原處**：上傳的人看得到審核結果；回報的人看得到處理結果。
3. **身分是登入的人，不是設定**：以帳號登入時不能切換身分；使用邀請碼體驗與展示模式可以切換。
4. **拒答也要給下一步**：只從目前身分看得到的內容產生建議（#247）。

### 展示功能的位置

| 功能 | 帳號登入 | 使用邀請碼體驗 | 展示模式（`?mode=presentation`） |
| --- | --- | --- | --- |
| 身分切換 | 不能切換；身分是登入的帳號 | 可以切換（現行） | 可以切換：身分對照、同題比較 |
| 預設問題與情境劇本 | 改成「常見問題」，依身分顯示 | 改成「常見問題」，依身分顯示 | 保留：劇本 |
| 「虛構資料 · 展示用權限」 | 只在參考情境與 demo 部署顯示 | 只在參考情境與 demo 部署顯示 | 保留 |
| 「這次的問題」 | 改成「問過的問題」，跨次保留，只存問題文字 | 改成「問過的問題」，跨次保留，只存問題文字 | 只保留這一次 |
| 首頁 | 登入後的預設頁 | 登入後的預設頁 | 不顯示，直接進問答 |

### 登入

knowledge-kit 的登入頁有兩條路，版面同「入口頁主視覺」（左側主視覺、右側登入面板）：

- **帳號登入**（主要）：是展示。帳號欄列出 `client/access.json` 各角色的虛構展示帳號（例如 `staff@example.test`），選了就固定為那個身分，登入後不能切換；密碼欄顯示但停用，placeholder 是「展示版不需要密碼」；輸入的內容不送出、不保存。fork 時換成客戶真的身分驗證。
- **使用邀請碼體驗**（下方的次要按鈕）：與現行相同，邀請碼對應 `client/access.json` 的角色，登入後可以切換身分。
- **`/api/ask` 仍以邀請碼把關**：線上 demo 以內建的公開碼（`VITE_PUBLIC_ACCESS_CODE`）送出，帳號登入不必另外輸入；沒有公開碼的部署，帳號登入頁也要輸入邀請碼。
- 登入時同時下載語意模型。展示模式（`?mode=presentation`）登入後直接進問答。
- **桌機（≥ 1025px）的版面**（#334，畫板 `K-Login`）：登入前沒有左側導覽，頂端一條細列（icon＋產品名稱／客戶名稱、「虛構資料」「展示用權限」標籤、右側語言選單）；主視覺佔滿左側，登入面板是右側寬 380～520px 的一欄。帳號是單選卡（展示帳號＋角色名稱，原生單選鈕，方向鍵切換）；「使用邀請碼體驗」與「改用帳號登入」在同一個面板切換，焦點移到新標題。平板與手機見「手機與平板」。

### 首頁

- **頂端**：依瀏覽器本地時間的問候：早安（5–11 時）、午安（12–17 時）、晚安（18–4 時）；不顯示名字或角色。
- **提問框**與依身分的**常見問題**。
- **一般員工：「有更新」**：上傳已核准或退回、審核中（說明「主管核准後才會出現在問答與圖譜」）、回報已處理；每則附一個動作（在圖譜查看、查看進度、看處理結果）。
- **主管：「等你處理」**：待審文件數、說法不同的組數、回報數（附最早一則的時間），每則一列，動作是「開始審核」或「處理回報」（都到待審頁）；數字是 0 的不列。導覽列「待審」的數字是待審文件加回報（與現行 `pendingCount()` 相同）。
- **問過的問題**：只存問題文字與提問時間（顯示成「今天」「昨天」等相對時間）；「再問一次」用現在看得到的資料重新回答，不保存舊的回答，避免權限改變後露出已經看不到的內容。
- **最近新增的文件**、**最近看過**的實體（點了在圖譜打開）。
- 所有清單與數字只算目前身分看得到的（#247）；空的時候用空狀態的共同元件。
- **桌機的版面**（#331，畫板 `K-Home`）：問候 28px，與左側欄的使用者卡分工，首頁不重複可見範圍；提問框是單行 52px 輸入框＋右側 52px「提問」，下方一列「常見問題」（36px 的中性按鈕）；卡片以 `repeat(auto-fit, minmax(340px, 1fr))` 排列，寬螢幕兩欄。「有更新」「等你處理」每則一列（`surfaceRaised` 底）：狀態點（核准 `success`、審核中 `primary`、說法不同 `conflict`、回報 `warning`、退回 `danger`）＋標題＋副標＋動作；問過的問題、最近新增的文件是 `border` 框的列；最近看過是圓角按鈕，前面是實體類型色的形狀（人圓形、部門圓角方形、其他小圓角）。平板維持單欄，可見範圍在問候下方。
- **手機的版面**（#356，畫板 `K-Mobile` 的首頁）：區塊不是卡片，標題與列直接放在 `background` 上；問候 22px；不顯示可見範圍（在身分與語言面板，#255）。提問框是單行輸入列（框內的「提問」），和其他區塊同寬（左右留白 16px，不是問答頁貼齊畫面的輸入列）；下方一行常見問題膠囊從同一條左緣開始，往右可以橫向滑出畫面。一般員工：「有更新 N」每則一列（`surface` 底、`border` 框，狀態點＋標題＋副標＋›），整列可以點；問過的問題每則一行（問題＋相對時間，下方 1px 的線），整行是「再問一次」。主管：最上方兩張數字卡（待審文件＋說法不同的組數、回報有錯＋最早一則的相對時間；有說法不同時第一張是 `conflict` 框）與「開始審核」，沒有待審時是空狀態；接著是提問框（「提問」改成框線按鈕）與最近新增的文件（mono 日期＋標題＋可見範圍）。其他區塊接在後面；觸控目標至少 44px。

### 我的上傳

- 送出後顯示四步進度：已上傳 → 萃取完成 → 等主管審核 → 出現在問答與圖譜；說明「主管核准後，內容才會出現在問答與圖譜」。
- 「上傳」頁分成「新增文件」與「我的上傳」。每份上傳一列，狀態是審核中、已核准、部分退回、已退回（全部退回，#284 決定 3；還沒有萃取出項目時是「已上傳」，決定 4）；點了在右側（手機為底部面板）顯示每一項實體與關係的結果。部分退回或已退回時「重新上傳修正版」，會重新送審。
- 資料來自 `documents.uploaded_by`、待審項目與審核決定。0006 的 RLS 只讓核准者讀得到待審資料，migration 0011 新增 policy，讓上傳的人讀得到自己上傳、而且看得到的文件的待審項目與審核決定（ADR 0009；`store.ts` 的 `readMyUploads()`）。

### 拒答的下一步

- 「可以試試」的建議從問題中**目前身分看得到的實體**產生：在圖譜看它、問它的負責人（例如「王小明（青翼專案負責人）」）、用它換個問法。
- 問題中沒有看得到的實體時，退回現行的通用建議。不論資料是否存在，畫面都一樣（#247）。

### 回報結果

回報有錯之後，結果回到回報的人：顯示在原本的回答下方與首頁「有更新」。

| 狀態 | 來源 | 畫面 |
| --- | --- | --- |
| 處理中 | 沒有處理紀錄 | 「主管還沒處理」 |
| 不是錯誤 | `not_error` | 處理日期＋說明（沒有說明時只顯示結果）＋「仍有疑問，再回報一次」 |
| 已撤回相關內容 | `retracted` | 處理日期＋說明＋「再問一次」 |

- 處理者只顯示角色，不顯示名字。主管處理時有一個選填的「給回報的人的說明」（500 字內）。
- **需要新的 migration**：目前只有能審核的身分讀得到回報（ADR 0007，[data-model.md「回答錯誤回報」](data-model.md#回答錯誤回報)），而且處理沒有說明欄位。做法（回報的人讀得到自己的回報，但送出的段落仍要全部看得到；處理說明欄）與要更新 ADR 0007 還是另開 ADR，在實作 Issue 中以 `plan-first` 討論。

### 手機

- **底部分頁列加入「首頁」並放在最左**：一般員工是首頁、問答、圖譜、時間軸、上傳；主管是首頁、問答、圖譜、上傳、更多（時間軸收進「更多」，與待審、評測台在一起）。「更多」的數字是待審加回報。
- **登入**：主視覺縮成上方 330px；帳號、停用的密碼欄、「登入」與下方的「使用邀請碼體驗」、模型下載進度在下方拇指可及的範圍。
- **首頁**：提問框在最上；一般員工的「有更新」只列三則，點了進對應頁面；主管把待審與回報的數字卡放最上方，下面是「開始審核」。
- **我的上傳**：點一份從底部升起詳情面板。回報結果沿用回答下方的卡片。

導覽列、手機分頁列（最長的 “Timeline” 44px，每格 78px）、平板導覽列、實體面板的按鈕、回答與引用不需要調整。回報處理的兩個按鈕在手機上放得下但很緊，窄於 360px 時改成上下排列。

### 排版規則

- **不固定寬度**：按鈕、分段、晶片只設最小寬度與內距；容器放不下時換行或捲動，不截斷動作文字。
- **可以截斷的只有名稱**（節點、文件標題、清單中的問題）；截斷時完整文字放在 `title` 與報讀器的名稱。
- **行高**：目前全站 1.6，英文維持；中文的長段落（原文、回答）可用 `:lang(zh-TW)` 放寬到 1.8。元件不分語言寫兩份。
- **字型**：Inter 在前、Noto Sans TC 在後；英文不用全大寫，標籤用句首大寫（“Sample questions”）。
- **標點**：英文用 “ ” 與半形標點；中文的「」不出現在英文字串中。
- **日期與數字**：一律用 `Intl`；數量放進文案的 `{count}`，英文另寫單複數。
- **實體名稱**來自資料的 `names[語言]`，清單與晶片允許換行。

## 圖譜的鍵盤操作與螢幕報讀器

圖譜畫在 cytoscape 的 canvas 上，螢幕報讀器讀不到節點。本節補兩條路：在圖上用方向鍵**沿著關係移動**（與展示模式的 ←／→、`Enter`、`A` 一致），以及**清單模式**這個完整的文字版本。

### 按鍵（一般模式，焦點在圖譜時）

| 按鍵 | 作用 |
| --- | --- |
| `Tab` | 進入圖譜：焦點落在選取的實體，沒有選取時落在關聯最多的實體；再按 `Tab` 離開到實體面板。圖譜內部不佔 Tab 順序 |
| `←`／`→` | 在目前實體的相關實體間移動游標（從 12 點鐘方向順時針） |
| `Enter` | 前往游標所在的實體：它成為目前的實體，實體面板同步；焦點留在圖譜 |
| `Backspace` | 回到上一個實體（走過的路徑） |
| `Space` | 選取或取消「只看它」 |
| `A` | 在問答中問目前的實體 |
| `/` | 跳到「搜尋名稱」；選了結果後焦點回到圖譜 |
| `+`／`-`／`0` | 放大、縮小、全部顯示；游標移到畫面外時自動平移（`sweep`，減少動態時直接到位） |
| `Esc` | 回到全部；在「回到全部」的狀態再按一次離開圖譜 |
| `?` | 顯示按鍵表 |

### 畫面

- **目前的實體**：`focus` 色 3px 實線圈。**游標**：`focus` 色虛線圈；連到目前實體的線加粗成 `primary`，線上標出關係名稱。Light／Dark 都用 `focus` token。
- 按鍵提示列只在鍵盤聚焦（`:focus-visible`）時出現在圖譜下方。

### 報讀

- 每一步寫進一個 `aria-live="polite"` 的區域，只說新的資訊；連按時只讀最後一次（200ms 去抖）。
- 句型（文字放 `client/i18n/`）：

| 時機 | 句型 |
| --- | --- |
| 進入圖譜 | 知識圖譜，{entities} 個實體、{relations} 段關係。目前：{name}，{type}，關聯 {count}。 |
| 移動游標 | {index}／{total}：{name}。{from} {relation} {to}。 |
| 前往 | 前往 {name}，{type}，關聯 {count}。 |
| 到頭了 | 已經是第一個實體。／沒有相關實體。 |
| 篩選後 | 顯示 {entities} 個實體。 |

- 關係一律說成「主詞 關係 受詞」的完整句子，方向不靠箭頭；同一對實體有多種關係時合併在同一句。同名實體沿用畫面上的消歧名稱（例如「林志明（產品研發部）」）。
- 數量、相關實體與關係都只算目前身分看得到的；不說「有些看不到」（#247）。

### 容器與清單模式

- 圖譜外框是一個可聚焦的元素：`role="application"`、`aria-roledescription`「知識圖譜」，讓方向鍵交給圖譜而不是報讀器的瀏覽模式。代價是使用者在圖譜內不能用報讀器原本的瀏覽方式，所以**清單模式必須一起提供**。
- **清單模式**：「圖譜｜清單」切換一直都在，不偵測報讀器。群組是 `h3`，實體是清單項目（名稱是按鈕，打開實體面板），關係是句子，句中的實體名稱是連結、跳到清單中的那一項。篩選、搜尋與「只看它」在兩種檢視下共用，切換時保留目前的實體；選擇記在這個瀏覽器。
- 減少動態時，游標移動與平移直接到位。
